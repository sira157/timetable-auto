## ส่วนที่ 1: สไตล์หน้าเว็บ (ต้นฉบับ: docs/style-guide.md)

# สไตล์หน้าตาเว็บ: ระบบจัดตารางสอนอัตโนมัติ (ให้ยึดตามนี้ทุกหน้า)

ใช้ React + TypeScript + Tailwind CSS v4 (ประกาศด้วย `@theme` และ `@utility` ในไฟล์ CSS หลัก) ทุกข้อความเป็นภาษาไทย

## 1. ฟอนต์และสีพื้นฐาน
- ฟอนต์: "Sarabun", "Noto Sans Thai", ui-sans-serif, system-ui, sans-serif
- line-height 1.55, ใช้ antialiased
- พื้นหลังทั้งหน้า: #f6f7fb (เทาอมฟ้าอ่อนมาก)
- สีตัวอักษรหลัก: slate-800
- สีหลักของแบรนด์: indigo-600 (#4f46e5), hover indigo-700 (#4338ca), อ่อน indigo-50 (#eef2ff), indigo-100 (#e0e7ff)
- สีโทนเน้นอื่น: violet-600 (ใช้คู่กับ indigo ในไล่สี), green (สำเร็จ), amber (เตือน), red (ผิดพลาด), slate (ข้อความรอง/เส้นขอบ)
- โฟกัสด้วยคีย์บอร์ด: outline 2px indigo-500, offset 2px, มุมโค้ง 0.5rem
- สีที่เลือกข้อความ (selection): indigo-100

## 2. ส่วนประกอบพื้นฐาน (utility classes)
- **card:** มุมโค้ง rounded-2xl, เส้นขอบ slate-200 โปร่งเล็กน้อย, พื้นขาว, padding 20px, เงาบางมาก (`0 1px 2px rgba(15,23,42,.04)`)
- **btn (ฐาน):** inline-flex, ความสูงต่ำสุด 40px, มุมโค้ง rounded-xl, ตัวอักษร 14px medium, มีเอฟเฟกต์กดย่อ (scale 0.98), ปิดใช้งานเป็นจางลง 50%
  - **btn-primary:** พื้นอินดิโก-600 ตัวอักษรขาว มีเงาอินดิโกจาง hover เป็นอินดิโก-700
  - **btn-ghost:** พื้นขาว เส้นขอบ slate-300 ตัวอักษร slate-700 hover พื้น slate-50 และเส้นขอบเข้มขึ้น
  - **btn-danger:** พื้นขาว เส้นขอบแดงอ่อน ตัวอักษรแดง hover พื้นแดงอ่อน
- **input:** สูงต่ำสุด 40px, มุมโค้ง rounded-xl, เส้นขอบ slate-300, padding 12px/8px, placeholder slate-400; hover เส้นขอบเข้มขึ้น; focus เส้นขอบอินดิโก-500 + วงแหวนอินดิโก-100 หนา 4px; disabled พื้น slate-50
- **label:** ตัวอักษร 14px medium สี slate-600 อยู่บนฟิลด์ เว้นล่าง 4px
- **ตาราง:** หัวตารางพื้น slate-50 ตัวหนา 600 สี slate-500; แถวที่ hover พื้นอินดิโก-50 โปร่ง 55%
- **Scrollbar:** บาง สี slate-300
- **Badge (ป้ายสถานะ):** มุมโคนกลม (pill), เส้นขอบบาง, ตัวอักษร 12px:
  - ผ่าน/พร้อม: เขียว (พื้น green-50, ตัว green-700)
  - เตือน: เหลืองอำพัน (amber)
  - ผิดพลาด: แดง
  - ซ้ำ/ไม่ใช้: เทา, นำออกแล้วมีขีดฆ่า
  - รอยืนยัน/ประเภทไม่รู้จัก: อินดิโก

## 3. โครงหน้า (Layout)
- **เดสก์ท็อป (md ขึ้นไป):** แถบซ้ายกว้าง 240px ติดหน้าจอ (sticky, เลื่อนภายในได้) พื้นขาว เส้นขอบขวา slate-200; ด้านขวาเป็นพื้นที่เนื้อหา
- **มือถือ:** แถบซ้ายซ่อนอยู่ กดปุ่ม ☰ ที่หัวด้านบนเพื่อเปิดเมนูแนวตั้งด้านบนเนื้อหา; กดลิงก์แล้วปิดเมนูอัตโนมัติ
- **หัวด้านบน (header):** ติดด้านบน (sticky) พื้นขาวโปร่ง 80% + blur, เส้นขอบล่าง, ชิดขวามีเมนูผู้ใช้
- **เนื้อหา:** กว้างสูงสุด 1152px (max-w-6xl) จัดกึ่งกลาง padding 16px บนมือถือ / 32px บนเดสก์ท็อป, ระยะบน-ล่าง 24px ยกเว้นหน้าตารางสอนใช้ความกว้างเต็มพื้นที่

### 3.1 แถบเมนูซ้าย (ลำดับจากบนลงล่าง)
1. **โลโก้:** SVG (`LogoMark` ใน `components/Illustrations.tsx`) ขนาด 36–38px กล่องมุมโค้ง พื้นไล่สีจาก indigo-500 ไป violet-600 ข้างในเป็นปฏิทินสีขาวที่มีช่องตารางสี (ฟ้า เขียว อินดิโก เหลือง) และวงกลมเขียวมีเครื่องหมายถูก มีเงาอินดิโกจาง ใช้เป็นไอคอนแท็บเบราว์เซอร์ด้วย; ข้อความ "ระบบจัดตารางสอน" (ตัวหนา 15px slate-800) และบรรทัดรอง "อัตโนมัติ" (12px indigo-600)
2. **หน้าแรก** (ไอคอนบ้าน)
3. **ขั้นตอนการทำงาน** (หัวข้อเล็กสี slate-400) มี 5 รายการ เรียงตามลำดับ มีตัวเลขกำกับด้านขวาสีจาง:
   - นำเข้าข้อมูล (ไอคอนลูกศรลง) 1
   - ตรวจสอบข้อมูล (ไอคอนเครื่องหมายถูก) 2
   - จัดตาราง (ไอคอนสายฟ้า) 3
   - ตารางสอน (ไอคอนตาราง) 4
   - รายงาน / ส่งออก (ไอคอนเอกสาร) 5
4. **กลุ่มยุบ/ขยายได้** (หัวข้อเล็กตัวหนาสี slate-400 มีลูกศร ›  หมุนเมื่อเปิด):
   - **ข้อมูลพื้นฐาน:** อาจารย์, รายวิชา, กลุ่มเรียน, ห้องเรียน, อาคาร, เรียนรวม, สอนร่วม, เวลาที่ไม่ว่าง, ข้อมูลไม่ลงทะเบียน
   - **ระบบ:** ตั้งค่าเงื่อนไข, บัญชีผู้ใช้, สำรองและล้างข้อมูล, ประวัติการแก้ไข, ประวัติการประมวลผล
- **รายการเมนู:** ตัวอักษร 14px, มุมโค้ง, padding 10px/8px. ที่เลือกอยู่: พื้นอินดิโก-50, ตัวหนา อินดิโก-700, มีแถบเส้นซ้ายอินดิโกหนา 3px. ที่ยังไม่เลือก: slate-600, hover พื้น slate-100
- **ไอคอนในรายการหลัก:** กล่องขนาด 28px มุมโค้ง พื้น slate-100 ไอคอนเส้น slate-500; ที่เลือกอยู่ กล่องเป็นอินดิโกเข้มตัวขาว
- **รายการในกลุ่มย่อย:** ซ้ายเยื้อง 16px ไม่มีไอคอน

### 3.2 หน้านำเข้าข้อมูลและหน้ากรอกข้อมูล
- หัวหน้านำเข้าข้อมูลมีปุ่มหลัก "กรอกข้อมูล" (ไอคอนดินสอ) ไปหน้า `/import/manual` และมีการ์ด "กรอกข้อมูลบนเว็บ" ในคอลัมน์ไฟล์ที่นำเข้าได้
- หน้ากรอกข้อมูลมีแท็บ ชั้นปีที่ N / ฝ่ายบริหาร / สถานที่เรียน ตามชีตของไฟล์ Excel ข้อมูลหลักสูตร; แต่ละกลุ่มเรียนเป็นการ์ด มีคอลัมน์ ที่ | รหัสวิชา | ชื่อรายวิชา | อาจารย์ผู้สอน | สถานที่ที่ใช้ | หน่วยกิต | กลุ่มวิชา บนมือถือเรียงเป็นฟอร์มแนวตั้ง
- วิชาในกลุ่มเลือกเดียวกันแสดงเยื้องพร้อมเส้นซ้ายสีฟ้า (sky-300) และลูกศร ↳
- แถบบันทึกติดด้านล่าง แสดงป้าย "ยังไม่บันทึก" และช่องยืนยันการแทนที่ข้อมูลเดิม

## 4. หน้าแรก (Dashboard)
- **แบนเนอร์ใหญ่บนสุด:** พื้นไล่สีจาก indigo-600 ไป violet-600, มุมโค้ง 16px, เงาบาง, ตัวอักษรขาว
  - บรรทัดเล็กต้อนรับ "สวัสดี {ชื่อ}" หรือ "ยินดีต้อนรับ" (สีอินดิโก-100)
  - หัวเรื่อง "ระบบจัดตารางสอนอัตโนมัติ" ตัวหนา 24px (บนจอใหญ่ 30px)
  - คำอธิบายสั้น ๆ สีอินดิโก-100
  - กล่องโปร่งแสงขวา (พื้นขาว 10%, blur) แสดง "ขั้นตอนถัดไป" + ชื่อขั้นตอน + ปุ่มสีขาวตัวอินดิโกตัวหนา มีลูกศร →
- **แถบแจ้งเตือน** (ถ้ามี): แดงอ่อนสำหรับการตั้งค่าเวลาไม่ถูกต้อง, เหลืองอ่อนสำหรับตารางที่ข้อมูลเปลี่ยนหลังจัด; กดได้ทั้งแถบ
- **การ์ดสถิติ 4 ใบ** (มือถือ 2 คอลัมน์ เดสก์ท็อป 4): กล่องไอคอนอินดิโก-50 + ป้าย + ตัวเลขตัวหนาใหญ่ (tabular-nums); ใบที่ไม่มีห้องแสดงคำเตือนเหลือง
- **แถว 2 ช่อง** (เดสก์ท็อป 5:2):
  - การ์ด "ตารางสอนปัจจุบัน" (กว้าง 3 ส่วน) พร้อมปุ่ม
  - การ์ด "ความพร้อมของข้อมูล" (กว้าง 2 ส่วน) มีแถบสัดส่วนสี่สี: เขียว (พร้อม), เหลืองอำพัน (ต้องตรวจ), แดง (ผิดพลาด), ม่วง (ไม่พบในทะเบียน); มีจุดสีนำหน้าแต่ละรายการ
- **แถวขั้นตอน 4 ใบ** (เดสก์ท็อป 4, มือถือ 2): ใบที่เป็น "ถัดไป" มีเส้นขอบอินดิโก-300 และวงแหวนอินดิโก-100; วงกลมเลข: เสร็จ = เขียวอ่อนพร้อมเครื่องหมาย ✓, ถัดไป = อินดิโกตัวขาว, อื่น ๆ = เทาอ่อน
- **ทางลัด 4 ใบ:** การ์ดมีไอคอนอีโมจิ หัวเรื่อง และคำอธิบายสั้น hover เส้นขอบอินดิโก-200
- **หน้าเริ่มต้น (ยังไม่มีข้อมูล):** หัวเรื่อง "เริ่มต้นใช้งาน — เลือกวิธีใส่ข้อมูล" และการ์ด 3 ใบ: ดาวน์โหลดแบบฟอร์ม / นำเข้าไฟล์ / กรอกบนเว็บ (ปุ่มหลักอินดิโก 1 ปุ่ม) พร้อมลิงก์ "ลองนำเข้าข้อมูลตัวอย่าง"

## 5. หน้าตารางสอน (ส่วนสำคัญที่สุด)
- การ์ดขาวมีหัวเรื่อง (ตัวหนา) และคำบรรยายรอง (สี slate-500) ขวาสุดเป็นข้อความเล็ก "X คาบ/สัปดาห์"
- แกนตั้ง = วัน (คอลัมน์ซ้ายกว้าง 80px ติดซ้ายตอนเลื่อน ตัวอักษรสีเข้ม)
- แกนนอน = คาบ 1–N หัวคอลัมน์ 2 บรรทัด: "คาบ N" (ตัวกลาง) และช่วงเวลา "08:00–09:00" (ตัวอ่อนสีจาง); หัวติดด้านบนตอนเลื่อน
- ต้องเห็นตารางเต็มโดยไม่ต้องเลื่อนแนวนอน: จอ md ขึ้นไป ตารางกว้างเท่าพื้นที่ (table-fixed ไม่มีความกว้างต่ำสุด) บนมือถือแสดงเป็นรายวัน (การ์ดละ 1 วัน เรียงคาบจากเช้าถึงเย็น คั่นด้วยแถบพักกลางวัน)
- มีปุ่ม "เต็มจอ" ดูตารางเต็มหน้าจอ (Fullscreen API) และ PDF ใช้แบบตารางเสมอ (ตอนสร้าง PDF ไม่ใช้ sticky และชื่อไฟล์แทน / ด้วย -)
- ช่องวิชาไม่แสดงคำกำกับ (ทฤษฎี) (ปฏิบัติ) (ทฤษฎี+ปฏิบัติ)
- มุมมองชั้นปี: วิชาเลือกที่เรียนเวลาเดียวกันเป็นกล่องเดียว และพักกลางวันเป็นแถบเดียวตลอดทุกวัน
- **ช่องวิชา (บล็อก):** ปุ่มเต็มช่อง มุมโค้ง 6px เส้นขอบบาง ความสูงต่ำสุด 64px ข้อความ 12px:
  - บรรทัดแรก: รหัสวิชาตัวหนา + ป้ายเล็กมุมโค้ง (เรียนรวมพื้นเขียวเข้มตัวขาว, สอนร่วมพื้นอินดิโกเข้มตัวขาว)
  - บรรทัดสอง: ชื่อวิชา (ตัดเหลือ 2 บรรทัด)
  - บรรทัดสาม: ครูหรือกลุ่ม (ตามมุมมอง) ตัดด้วย …
  - บรรทัดสี่: ห้อง หรือ กลุ่ม
- **ช่องกว้างตามจำนวนคาบ:** วิชาที่ยาวหลายคาบต่อเนื่องจะขยายข้ามคอลัมน์ (colSpan) เส้นแบ่งคอลัมน์ slate-100
- **หลายช่องพร้อมกัน (lanes):** วันเดียวกันที่มีกิจกรรมคู่ขนานจะแยกเป็นแถวย่อยภายในวันเดียวกัน แถวหลักของแต่ละวันคั่นด้วยเส้น slate-200
- **สีบล็อก:**
  - วิชาปกติ: พื้น sky-50, เส้น sky-200, ตัว sky-900
  - เรียนรวม: พื้น green-50, เส้น green-200, ตัว green-900
  - สอนร่วม: พื้น indigo-50, เส้น indigo-200, ตัว indigo-900
  - กิจกรรม: พื้น violet-50, เส้น violet-200, ตัว violet-800
  - ประชุม: พื้น slate-100, เส้น slate-300, ตัว slate-700
  - พักกลางวัน: พื้น amber-50, เส้น amber-200, ตัว amber-800
- **คำอธิบายสี (legend)** ใต้ตาราง: กล่องสี่เหลี่ยมเล็ก 12×20px + ชื่อ เรียงในแถว วิชาปกติ, เรียนรวม, สอนร่วม, กิจกรรม, ประชุม, พักกลางวัน; ถ้าไม่มีแถบพักในตาราง จะมีหมายเหตุ "ช่องว่างช่วงกลางวัน = เวลาพัก"
- ตารางจากมุมมอง ครู / กลุ่ม / ห้อง / อาคาร มีรูปแบบเดียวกันและเปลี่ยนเฉพาะข้อความในบล็อก

- PDF: ทุกตารางเริ่มหน้าใหม่ วันอยู่คอลัมน์ซ้าย ข้อความในบล็อกแสดงเต็ม ใต้ตารางมี "รายวิชาในตาราง" (ที่ / รหัสวิชา / ชื่อรายวิชา / หน่วยกิต / อาจารย์ผู้สอน หรือชั้นปี/กลุ่ม / สถานที่ที่ใช้ / วันและคาบ / คาบ/สัปดาห์) ถ้าไม่พอหน้าเดียวให้ขึ้นหน้าใหม่ และมีชื่อตารางรุ่นกับเวลาพิมพ์ท้ายหน้า

## 6. หน้าต่างโมดัล (Modal)
- ฉากหลังดำโปร่ง 40% ซ่อนตัว
- บนมือถือ: โมดัลติดล่าง มุมบนโค้ง 16px เต็มความกว้าง; บนจอกว้าง: อยู่กลาง มุมโค้งทุกด้าน กว้างสูงสุด 512px (กว้าง: 768px)
- หัวโมดัล: หัวเรื่องตัวหนา เส้นขอบล่าง ปุ่ม × ขวาสุด สีเทา
- ส่วนท้ายโมดัล: ปุ่มชิดขวา เส้นขอบบน
- กด Esc เพื่อปิด, คลิกนอกกรอบเพื่อปิด

## 7. ภาพประกอบ
- ภาพประกอบเป็น SVG ในตัว (`components/Illustrations.tsx`) ใช้สีชุดเดียวกับระบบ และต้องอธิบายการใช้งานได้ ไม่ใช่ตกแต่งอย่างเดียว
  - `TimetableArt`: ภาพตารางสอน (หน้าเข้าสู่ระบบ แบนเนอร์หน้าแรก)
  - `WorkbookArt`: ไฟล์ Excel ข้อมูลหลักสูตรพร้อมแท็บชีต (หน้านำเข้า หน้าเริ่มต้นใช้งาน)
  - `PipelineArt`: ขั้นตอนการจัดตาราง (หน้าจัดตาราง ปุ่มหลักชื่อ "จัดตาราง")
  - `Ring`: วงแหวนสัดส่วนชั่วโมงที่จัดได้ (การ์ดตารางสอนปัจจุบัน)

## 8. หลักการทั่วไป
- ไม่ใช้เงาแรง ใช้เส้นขอบบางและพื้นหลังอ่อนแทน
- มุมโค้งเป็นหลัก: การ์ด 16px, ปุ่มและฟิลด์ 12px, ป้ายและบล็อกเล็ก 6–8px
- ตัวเลขที่เปลี่ยนค่าใช้ tabular-nums
- ปุ่มทุกปุ่มมีขนาดแตะได้อย่างน้อย 40px
- สถานะเตือนด้วยสีและข้อความ ไม่ใช้สีอย่างเดียว
- ทั้งระบบเป็นธีมสว่างเท่านั้น
- ใช้ได้ทั้งคอมและมือถือ ไม่มีการเลื่อนแนวนอนทั้งหน้า ขอบซ้ายขวา 16px

## ส่วนที่ 2: เงื่อนไขการจัดตารางสอน (ต้นฉบับ: docs/scheduling-rules.md)

# เงื่อนไขการจัดตารางสอนอัตโนมัติ (กฎของระบบ)

จัดตารางสอนอัตโนมัติสำหรับหลักสูตรหนึ่งของมหาวิทยาลัย โดยใช้ข้อมูลรายวิชา ผู้สอน กลุ่มเรียน และสถานที่เรียนที่แนบมา และปฏิบัติตามเงื่อนไขทุกข้อต่อไปนี้ ข้อมูลต้องจัดลงตัว (ทุกรายวิชาได้ครบชั่วโมงโดยไม่ขัดเงื่อนไขบังคับ) หากเงื่อนไขใดขัดกัน ให้ยึดเงื่อนไขที่จัดการยากที่สุดก่อน

> หมายเหตุ: ไฟล์นี้เก็บ "กฎ" เท่านั้น ข้อมูลจริง (รายวิชา ผู้สอน กลุ่มเรียน ห้อง สนาม รายชื่อฝ่ายบริหาร ฯลฯ) อาจมีการแก้ไขภายหลัง จึงไม่ควรฝังค่าเหล่านั้นลงในโค้ด ให้อ่านจากไฟล์ข้อมูลแยกต่างหาก
>
> ปรับปรุงล่าสุด 26 พ.ย. 2569: ใช้เงื่อนไขชุดใหม่จากผู้จัดตารางเป็นหลัก (ข้อ 1.4–1.5, 2.5, 3.4, 4.1, 8.6–8.7, 9 และ 6.1 เปลี่ยนจากฉบับก่อน)

## อัลกอริทึมที่ใช้
- ใช้ Constraint Programming (CP-SAT ของ Google OR-Tools) เป็นตัวจัดหลัก: เงื่อนไขบังคับเขียนเป็นข้อจำกัดที่ห้ามละเมิด และเป้าหมายรองเป็นค่าปรับในฟังก์ชันเป้าหมาย ตัวแก้จะหาคำตอบที่จัดครบได้ถ้ามีอยู่จริง หรือรายงานว่าข้อมูลจัดลงตัวไม่ได้
- ใช้ผลจากวิธีละโมบ (greedy) แบบสุ่มเริ่มใหม่เป็นคำตอบตั้งต้น (hint) และเป็นตัวสำรองเมื่อไม่มี OR-Tools

## 1. ช่วงเวลาเรียน
1.1 จัดตารางวันจันทร์ถึงวันศุกร์ (5 วัน)
1.2 วันละ 9 คาบ คาบละ 60 นาที คาบที่ 1 เริ่ม 08:00 น. ถึงคาบที่ 9 สิ้นสุด 17:00 น.
   - คาบ 1 08:00–09:00, คาบ 2 09:00–10:00, คาบ 3 10:00–11:00, คาบ 4 11:00–12:00
   - คาบ 5 12:00–13:00 เป็นเวลาพักเที่ยงของนักศึกษาทุกห้องทุกชั้นปี ห้ามจัดการเรียนการสอน
   - คาบ 6 13:00–14:00, คาบ 7 14:00–15:00, คาบ 8 15:00–16:00, คาบ 9 16:00–17:00
1.3 ห้ามจัดคาบเรียนคร่อมเวลาพักเที่ยง
1.4 วันพุธ คาบ 8 เป็นคาบ "พบอาจารย์ที่ปรึกษา" ของทุกห้องทุกชั้นปี ห้ามจัดการเรียนการสอนให้นักศึกษา และอาจารย์ที่ปรึกษาต้องว่างในคาบนี้
1.5 วันพุธ คาบ 9 เป็นคาบ "กิจกรรม" ของทุกห้องทุกชั้นปี ห้ามจัดการเรียนการสอน

## 2. การคำนวณชั่วโมงเรียน
2.1 หน่วยกิตเขียนในรูปแบบ น(ท-ป-ศ) เช่น 3(2-2-5)
2.2 จำนวนชั่วโมงเรียนต่อสัปดาห์ = ชั่วโมงทฤษฎี + ชั่วโมงปฏิบัติ ไม่นับชั่วโมงศึกษาด้วยตนเอง เช่น 3(2-2-5) เรียน 4 ชั่วโมงต่อสัปดาห์ และ 2(1-2-3) เรียน 3 ชั่วโมงต่อสัปดาห์
2.3 แบ่งชั่วโมงเรียนของแต่ละวิชาเป็นชุดคาบติดกัน ชุดละไม่เกิน 3 คาบ โดยแยกชุดทฤษฎี (บรรยาย) กับชุดปฏิบัติ เช่น 3(2-2-5) = ทฤษฎี 2 + ปฏิบัติ 2, 3(3-0-6) = ทฤษฎี 3, 4(3-2-7) = ทฤษฎี 3 + ปฏิบัติ 2 ยกเว้นวิชากีฬาตามข้อ 9.1 ที่ทฤษฎีและปฏิบัติอยู่ในชุดเดียวกัน (ชุดละไม่เกิน 3 คาบ)
2.4 ชุดคาบของวิชาเดียวกันต้องอยู่คนละวัน ยกเว้นชุดทฤษฎีกับชุดปฏิบัติของวิชาเดียวกันที่เรียนต่อเนื่องกัน (ข้อ 11.6) ซึ่งอยู่วันเดียวกันได้
2.5 นักศึกษาชั้นปีที่ 4 เรียนรายวิชา กศ 021037 ปฏิบัติการสอนในสถานศึกษา 4 6(360) ฝึกปฏิบัติงานและสอนจริงในสถานศึกษาตลอดทั้งภาคเรียน ไม่มีการจัดตารางเรียน ผู้สอนมีหน้าที่รับผิดชอบรายวิชาเท่านั้นและไม่มีคาบสอน (ตารางของชั้นปีขึ้นหัวว่า "ปฏิบัติการสอนในสถานศึกษา" พร้อมชื่ออาจารย์ที่ปรึกษา และตารางของผู้สอนแสดงว่ารับผิดชอบรายวิชาโดยไม่มีคาบสอน) วิชาที่มีชื่อ "ปฏิบัติการสอนในสถานศึกษา" "ปฏิบัติสอนในสถานศึกษา" หรือ "ฝึกประสบการณ์วิชาชีพ" ใช้กฎเดียวกัน

## 3. ผู้สอน
3.1 ผู้สอนหนึ่งคนสอนได้ครั้งละหนึ่งวิชาเท่านั้น ห้ามสอนซ้อนเวลา
3.2 วิชาที่มีผู้สอน 2 คน (สอนร่วม) ผู้สอนทั้ง 2 คนต้องมีคาบสอนพร้อมกันกับนักศึกษาในห้องนั้น และนับจำนวนคาบสอนให้ผู้สอนทั้ง 2 คน
   - ตารางของชั้นปี/กลุ่มเรียนต้องขึ้นชื่อผู้สอนทั้งสองคน
   - ตารางอาจารย์ต้องขึ้นวิชาที่สอนพร้อมรายชื่อผู้สอนร่วมอีกคน
3.3 ห้ามจัดสอนในเวลาที่ผู้สอนติดประชุมหรือกิจกรรม
3.4 อาจารย์ที่มีรายชื่อในชีต "ฝ่ายบริหาร" ประชุมทุกวันอังคาร คาบ 1–4 (08:00–12:00) ไม่จัดให้มีการสอนในช่วงเวลานั้น
3.5 ไม่จำกัดจำนวนชั่วโมงสอนต่อวันของผู้สอน
3.6 หากผู้สอนมีชั่วโมงสอนรวมมากกว่าจำนวนคาบที่เปิดสอนต่อสัปดาห์ ให้แจ้งว่าจัดไม่ได้พร้อมเหตุผล

## 4. กลุ่มเรียน
4.1 กลุ่มเรียนมี 4 ชั้นปี ได้แก่ ปี 1 จำนวน 4 กลุ่ม กลุ่มละ 30 คน, ปี 2 จำนวน 4 กลุ่ม กลุ่มละ 30 คน, ปี 3 จำนวน 3 กลุ่ม กลุ่มละ 25 คน และปี 4 จำนวน 3 กลุ่ม กลุ่มละ 20 คน (จำนวนจริงอ่านจากไฟล์ข้อมูล)
4.2 กลุ่มเรียนหนึ่งกลุ่มเรียนได้ครั้งละหนึ่งวิชาเท่านั้น ห้ามเรียนซ้อนเวลา
4.3 ในวันเดียวกัน แต่ละกลุ่มเรียนต้องมีคาบว่างระหว่างวิชาไม่เกิน 3 คาบ (ไม่นับเวลาพักเที่ยง) หากจัดไม่ได้ครบทุกวิชา ให้ผ่อนเงื่อนไขข้อนี้ได้ และแจ้งเป็นคำเตือน
4.4 ห้ามจัดเรียนในเวลาที่กลุ่มเรียนติดกิจกรรม

## 5. วิชาเรียนรวม
5.1 วิชาที่ระบุว่า "รวม" ให้ทุกกลุ่มในชั้นปีเดียวกันเรียนพร้อมกันในคาบเดียวกัน
5.2 ให้ใช้ห้องสำหรับเรียนรวมก่อน ได้แก่ ห้องประชุม 1 และห้องประชุม 2 (จุได้ 120 คน)

## 6. วิชาเลือกกลุ่มทักษะและการสอนกีฬาขั้นสูง / การตัดสินกีฬา / กลวิธีการฝึกกีฬา
6.1 นักศึกษาเลือกเรียน 1 รายวิชา ให้จัดทุกรายวิชาในกลุ่มไว้ในเวลาเดียวกัน โดยแต่ละรายวิชาใช้ทั้งห้องเรียนทฤษฎีและโรงยิมหรือสนาม (ภาคปฏิบัติ) ในช่วงเวลาเดียวกัน
6.2 ล็อกช่วงเวลาสำหรับวิชาเลือกไว้ได้ (ล็อกคาบใดคาบหนึ่งของกลุ่มวิชาเลือกในหน้าตารางสอน ทุกรายวิชาในกลุ่มจะถูกล็อกเวลาเดียวกันและคงไว้เมื่อจัดใหม่) หากไม่ล็อก ระบบจะหาช่วงเวลาที่ทุกรายวิชาในกลุ่มลงได้พร้อมกัน
6.3 กลุ่มวิชาเลือกที่มีวิชาเดียว ให้จัดแยกตามกลุ่มเรียนเหมือนวิชาปกติ
6.4 ในเวลาที่จัดวิชาเลือก ผู้เรียนในชั้นปีนั้นไม่มีวิชาอื่นซ้อน

## 7. วิชาเลือกเสรี
7.1 วิชาในหมวดวิชาเลือกเสรีทุกวิชา จัดในวันศุกร์ คาบ 6–9 (13:00–17:00) และเริ่มเรียนพร้อมกันทุกวิชา
7.2 วิชาเลือกเสรีเรียนในห้องเรียนประจำของชั้นปี 1–4 โดยให้ใช้ห้องประจำของชั้นปีเดียวกันก่อน
7.3 ผู้สอนวิชาเลือกเสรีเป็นผู้เดินไปสอนที่ห้องเรียน

## 8. สถานที่เรียน
8.1 ห้องเรียน ห้องคอมพิวเตอร์ ห้องประชุม โรงยิม และสนาม อ่านจากไฟล์ข้อมูลห้อง
8.2 สนามและโรงยิมแบ่งเป็น "จุด" แต่ละจุดใช้สำหรับกีฬาที่กำหนด (รายละเอียดอยู่ในไฟล์ข้อมูลสนาม)
8.3 สถานที่เรียนหนึ่งแห่งใช้ได้ครั้งละหนึ่งวิชา ห้ามใช้ซ้อนเวลา
8.4 จำนวนที่นั่งของห้องเรียนต้องเพียงพอกับจำนวนผู้เรียน
8.5 กลุ่มเรียนแต่ละกลุ่มมีห้องเรียนประจำตามที่กำหนดในข้อมูลกลุ่มเรียน
8.6 รายวิชากลุ่มวิชาภาษา, วิชาสังคมศาสตร์และมนุษยศาสตร์, วิชาชีพครู, วิชาบังคับ, คณิตศาสตร์ และวิทยาศาสตร์ จัดชั่วโมงบรรยายและภาคปฏิบัติในห้องเรียนประจำของกลุ่ม
8.7 รายวิชากลุ่มนวัตกรรมและเทคโนโลยี จัดชั่วโมงบรรยายและภาคปฏิบัติในห้องคอมพิวเตอร์

## 9. วิชาที่ใช้โรงยิม/สนาม (กลุ่มทักษะและการสอนกีฬา)
9.1 รายวิชากลุ่มทักษะและการสอนกีฬา จัดชั่วโมงเรียนทั้งห้องเรียนทฤษฎี (ห้องประจำ) และโรงยิมหรือสนามที่ใช้ในช่วงเวลาเดียวกัน เช่น พล 051383 ทักษะการเรียนรู้กีฬากระบี่กระบอง 2(1-2-3) จัดชั่วโมงสอน 3 ชั่วโมง โดยจองทั้งห้องเรียนบรรยายและโรงยิมหรือสนามในช่วงเวลาเดียวกัน
9.2 ใช้สนามหรืออาคารตามที่ระบุในคอลัมน์ "สถานที่ใช้" ของไฟล์ข้อมูล หากระบุไว้หลายจุด (คั่นด้วยเครื่องหมายจุลภาค) ให้เลือกจุดใดจุดหนึ่งที่ว่าง
9.3 หากไม่ระบุจุด ให้เลือกจุดที่รองรับกีฬาของวิชานั้น

## 10. คาบที่ล็อกไว้
10.1 คาบที่ผู้ใช้ล็อกไว้ ต้องคงวัน คาบ และสถานที่เรียนเดิม เมื่อจัดตารางใหม่

## 11. เป้าหมายรอง (ทำให้ดีขึ้นหลังจากจัดได้ครบ)
11.1 คาบว่างระหว่างวันของกลุ่มเรียนไม่เกินข้อ 4.3
11.2 ชุดคาบทฤษฎี (บรรยาย) จัดช่วงเช้า (คาบ 1–4) และชุดคาบปฏิบัติจัดช่วงบ่าย (คาบ 6–9) ให้มากที่สุด วิชากีฬาที่ชั่วโมงปฏิบัติมากกว่าทฤษฎีถือเป็นชุดปฏิบัติ
11.3 หลีกเลี่ยงการจัดเรียนในคาบท้ายของวัน
11.4 ใช้ห้องลำดับแรกก่อน (ห้องประจำชั้นปีเดียวกัน, ห้องเรียนรวม)
11.5 ลำดับความสำคัญ: จัดครบทุกชั่วโมง > คาบว่างไม่เกินกำหนด > ทฤษฎี+ปฏิบัติห้องเดิมเรียนต่อเนื่อง (ข้อ 11.6) > ทฤษฎีเช้า/ปฏิบัติบ่าย > เลี่ยงคาบท้าย > ลำดับห้อง
11.6 วิชาที่มีทั้งชุดทฤษฎีและชุดปฏิบัติที่เรียนห้องเดิม พยายามจัดให้เรียนต่อเนื่องกันในวันเดียวกันและห้องเดียวกัน (ไม่ใช่เงื่อนไขบังคับ) "ต่อเนื่อง" หมายถึงชุดหนึ่งเริ่มทันทีที่อีกชุดจบ หรือคั่นด้วยเวลาพักเที่ยงเท่านั้น เช่น ทฤษฎีคาบ 3–4 แล้วปฏิบัติคาบ 6–7

## 12. ขั้นตอนการจัดตาราง
12.1 จัดวัน คาบ และสถานที่เรียนของทุกวิชาพร้อมกันในแบบจำลองเดียว (CP-SAT) ตามเงื่อนไขข้อ 1–10
12.2 คาบว่างเกินข้อ 4.3 เป็นค่าปรับ ไม่ใช่ข้อห้าม เพื่อให้จัดวิชาได้ครบก่อน และแจ้งเป็นคำเตือนเมื่อเกิดขึ้น
12.3 วิชาที่จัดไม่ได้ ให้แสดงรายการพร้อมเหตุผล

## 13. การตรวจสอบผลลัพธ์
ตรวจสอบตารางที่ได้ทุกคาบ และรายงานผลแยกเป็น "ข้อผิดพลาด" และ "คำเตือน" ดังนี้
- ข้อผิดพลาด: ผู้สอนสอนซ้อน, กลุ่มเรียนเรียนซ้อน, สถานที่เรียนถูกใช้ซ้อน, ทับเวลาพักเที่ยง, ทับคาบพบอาจารย์ที่ปรึกษาหรือคาบกิจกรรม, อยู่นอกช่วงคาบที่เปิดสอน, ผู้สอนติดประชุมฝ่ายบริหารหรือกิจกรรม, ชั่วโมงเรียนไม่ครบหรือเกิน, ยังไม่มีห้องเรียน, ไม่ได้เรียนที่ห้องประจำ, วิชานวัตกรรมและเทคโนโลยีไม่ได้เรียนในห้องคอมพิวเตอร์, วิชาเลือกเสรีไม่อยู่ในเวลาหรือห้องที่กำหนด, วิชาเลือกในกลุ่มเดียวกันไม่อยู่เวลาเดียวกัน, สนามไม่รองรับกีฬาของวิชา, วิชาที่ไม่ต้องจัดถูกจัดลงตาราง
- คำเตือน: คาบว่างระหว่างวันเกิน 3 คาบ, ที่นั่งไม่พอ, ยังไม่มีโรงยิม/สนาม, ยังไม่มีผู้สอน, ชุดคาบวิชาเดียวกันอยู่วันเดียวกันแต่ไม่ต่อเนื่อง

## 14. รูปแบบผลลัพธ์
แสดงตารางสอนแยกตามกลุ่มเรียน ผู้สอน และสถานที่เรียน พร้อมจำนวนชั่วโมงรวมต่อสัปดาห์ แต่ละคาบต้องแสดง
- ไม่แสดงคำกำกับภาค (ทฤษฎี) (ปฏิบัติ) (ทฤษฎี+ปฏิบัติ) ในช่องวิชา
- ตารางชั้นปี (กลุ่มเรียน/ห้องเรียน): รหัสวิชา ชื่อวิชา หน่วยกิต ชื่ออาจารย์ผู้สอน (สอนร่วมแสดงทุกคน) สถานที่เรียน
  - วิชาเลือกที่เรียนเวลาเดียวกันแสดงเป็นกล่องเดียว หัวกล่อง "วิชาเลือก" พร้อมชื่อกลุ่มวิชา และรายละเอียดทุกวิชาในกล่อง
  - พักกลางวันแสดงเป็นแถบเดียวตลอดทุกวัน
  - ชั้นปีที่ฝึกสอนทั้งภาคเรียนแสดงรายวิชาและอาจารย์ผู้รับผิดชอบ
- ตารางอาจารย์: รหัสวิชา ชื่อวิชา หน่วยกิต ชั้นปี/กลุ่มที่สอน สถานที่สอน (สอนร่วมแสดงชื่อผู้สอนร่วม)
- ตารางสถานที่: รหัสวิชา ชื่อวิชา หน่วยกิต อาจารย์ผู้สอน กลุ่มเรียน

## 15. ข้อมูลนำเข้าและส่งออก
- นำเข้าได้จากไฟล์ Excel (.xlsx), CSV (แยกไฟล์ตามชนิดข้อมูล หรือรวมใน .zip) และ JSON หรือกรอกบนเว็บในหน้า "กรอกข้อมูล" (ปุ่มอยู่ในหน้านำเข้าข้อมูล) ซึ่งใช้โครงสร้างเดียวกับไฟล์ Excel ข้อมูลหลักสูตร และบันทึกผ่านตัวอ่านเดียวกัน (คงอาจารย์ที่ปรึกษา หมายเหตุ และสถานะไม่ลงทะเบียนเดิมไว้)
- รูปแบบหลักคือไฟล์ Excel "ข้อมูลหลักสูตร" แบบแยกชีตชั้นปี (ชีต ชั้นปีที่ N, ฝ่ายบริหาร, สถานที่เรียน) แบบฟอร์มและไฟล์ข้อมูลปัจจุบันที่ระบบส่งออกใช้รูปแบบเดียวกันนี้ จึงแก้แล้วนำเข้ากลับได้
  - นำเข้าไฟล์นี้จะแทนที่ข้อมูลอาจารย์ กลุ่มเรียน ห้อง รายวิชา และการเปิดสอน แต่ไม่ลบเวลาที่ไม่ว่างที่กรอกไว้ในระบบ
  - วิชาเลือกที่แต่ละกลุ่มระบุสถานที่ไม่ตรงกัน ใช้สถานที่ที่รองรับกีฬาของวิชาก่อน และแจ้งให้ตรวจ
  - "สถานที่ที่ใช้" ที่ระบุต่อกลุ่มเรียน ถือตามข้อมูล (ใช้แทนห้องที่ระบบเลือก) ถ้าระบุเฉพาะสนาม ไม่ต้องใช้ห้องเรียน
  - หน่วยกิตแบบ "1(90) เรียน 4 ชม." ใช้ชั่วโมงตามที่ระบุ และ "เรียนรวมทั้งชั้นปี" = ทุกกลุ่มเรียนพร้อมกัน (ถ้าแต่ละกลุ่มระบุห้องต่างกัน ให้เรียนเวลาเดียวกันคนละห้อง)
  - แถววิชาที่ไม่มีเลขลำดับต่อจากวิชาที่ "เลือกเรียน" = วิชาในกลุ่มเลือกเดียวกัน (จัดเวลาเดียวกัน)
  - ชื่ออาจารย์ที่ต่างกันเฉพาะคำนำหน้า/ยศ/ตำแหน่ง ถือเป็นคนเดียวกัน
- ส่งออกได้เป็น PDF, Excel และ CSV

## ส่วนที่ 3: ระบบล็อกอินและสิทธิ์การใช้งาน (ต้นฉบับ: docs/auth-rules.md)

# พรอมต์ระบบล็อกอินและสิทธิ์การใช้งาน: ระบบจัดตารางสอนอัตโนมัติ

สร้างระบบล็อกอินสำหรับเว็บจัดตารางสอน (FastAPI + SQLAlchemy + SQLite ฝั่ง backend, React + TypeScript ฝั่ง frontend) ทุกข้อความที่ผู้ใช้เห็นเป็นภาษาไทย หลักการคือ **ปฏิเสธทุกอย่างที่ไม่ได้อนุญาตไว้อย่างชัดเจน** (deny by default)

## 1. บทบาท (role) 3 แบบ
| role | ชื่อที่แสดง | สิทธิ์ |
|---|---|---|
| `staff` | ผู้ดูแลเว็บไซต์ | ดู/แก้ไขทุกอย่าง รวมถึงจัดการบัญชีผู้ใช้ |
| `teacher` | อาจารย์ | ดูได้เฉพาะตารางสอนของอาจารย์ที่บัญชีนั้นผูกไว้ (`scope_id` = id ของครู) |
| `student` | นักเรียน | ดูได้เฉพาะตารางของกลุ่มเรียน/ห้องเรียนที่บัญชีนั้นผูกไว้ (`scope_id` = id ของกลุ่มเรียน) |

- บัญชี `staff` ต้องไม่มี `scope_id` (เป็น null เสมอ)
- บัญชี `teacher` และ `student` ต้องระบุ `scope_id` ทุกครั้ง

## 2. ฐานข้อมูลและบัญชี
- ตาราง `UserAccount`: `id`, `username` (เก็บตัวพิมพ์เล็กเสมอ, ไม่ซ้ำ), `display_name`, `role`, `scope_id`, `password_hash`, `must_change_password` (boolean), `is_active` (boolean, ค่าเริ่มต้น true), `last_login_at` (UTC)
- **รหัสผ่าน** เก็บด้วย PBKDF2-HMAC-SHA256, 200,000 รอบ, salt 16 ไบต์สุ่ม, รูปแบบ `pbkdf2$<รอบ>$<salt hex>$<hash hex>` ห้ามเก็บรหัสผ่านเป็นข้อความธรรมดา และเทียบด้วย `hmac.compare_digest`
- **ความยาวรหัสผ่านขั้นต่ำ 6 ตัวอักษร** ตรวจทั้งฝั่ง backend และ frontend
- **บัญชีผู้ดูแลเริ่มต้น:** ถ้าฐานข้อมูลยังไม่มีบัญชี `staff` เลย ให้สร้างบัญชี `admin` ชื่อแสดง "ผู้ดูแลเว็บไซต์" โดยใช้รหัสจากตัวแปรสภาพแวดล้อม `TIMETABLE_ADMIN_PASSWORD` ถ้าไม่ได้ตั้งไว้ใช้รหัส `admin1234` และตั้ง `must_change_password = true` (ใช้ตอนพัฒนาเท่านั้น ต้องตั้งค่า env ก่อนขึ้นระบบจริง)
- ห้ามปิดใช้งานบัญชี `staff` ที่เป็นบัญชีสุดท้าย และห้ามลบบัญชี `staff` ที่เป็นบัญชีสุดท้าย
- ห้ามลบบัญชีที่กำลังใช้งานอยู่ของตัวเอง

## 3. โทเคนและการเข้าสู่ระบบ
- โทเคนเป็นรูปแบบ `<payload base64url>.<ลายเซ็น HMAC-SHA256 hex>`
  - payload ประกอบด้วย `uid`, `exp` (หมดอายุ **12 ชั่วโมง**), และ `pv` (ลายนิ้วมือจาก 16 ตัวท้ายของ `password_hash`)
  - คีย์ลงนาม (`auth_secret`) สุ่ม 32 ไบต์ เก็บในตาราง `app_settings` และสร้างครั้งแรกเมื่อจำเป็น
- **การตรวจโทเคน:** ตรวจลายเซ็นด้วย `compare_digest`, ตรวจวันหมดอายุ, บัญชียังใช้งานอยู่ (`is_active`), และ `pv` ตรงกับรหัสผ่านปัจจุบัน
  - ผลคือ **เมื่อเปลี่ยนหรือรีเซ็ตรหัสผ่าน โทเคนเดิมทุกอันของบัญชีนั้นใช้ไม่ได้ทันที**
- **การล็อกอิน** `POST /api/auth/login` รับ `username`, `password`
  - ตัดช่องว่างและแปลงชื่อเป็นตัวพิมพ์เล็กก่อนค้นหา
  - ตรวจรหัสผ่านเสมอแม้ไม่พบชื่อ (ใช้ hash จำลอง) เพื่อไม่ให้เดาได้ว่าชื่อผู้ใช้มีอยู่หรือไม่
  - ตอบข้อความเดียวกันเสมอเมื่อล็อกอินไม่ผ่าน: "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง"
  - สำเร็จ: อัปเดต `last_login_at` และคืน `{ token, user }`
- **จำกัดการลองผิด:** นับความพยายามผิดตามคู่ (IP | ชื่อผู้ใช้) ถ้าผิด **5 ครั้งภายใน 5 นาที** ให้ตอบ 429 "ใส่รหัสผิดหลายครั้ง กรุณารอ 5 นาทีแล้วลองใหม่" การนับเก็บในหน่วยความจำ (รีสตาร์ตเซิร์ฟเวอร์แล้วจะเคลียร์)
- `GET /api/auth/me` คืนข้อมูลผู้ใช้ปัจจุบัน
- `POST /api/auth/password` รับ `old_password`, `new_password`
  - ตรวจรหัสเดิมให้ถูก, รหัสใหม่ยาว ≥ 6, รหัสใหม่ต้องไม่ซ้ำรหัสเดิม
  - ตั้ง `must_change_password = false` แล้วคืนโทเคนใหม่ให้ทันที

## 4. ตัวป้องกัน (guard) ทุก API
- ทุกเส้นทางใต้ `/api` ต้องผ่าน guard กลางนี้ ยกเว้น:
  - `POST /api/auth/login` และ `GET /api/health` (สาธารณะ)
  - `GET /api/auth/me` และ `POST /api/auth/password` (ใช้ได้เฉพาะเมื่อล็อกอินแล้ว แม้ยังต้องเปลี่ยนรหัส)
- ส่งโทเคนใน header `Authorization: Bearer <token>`
- ไม่มีโทเคนหรือโทเคนไม่ถูกต้อง → **401** "กรุณาเข้าสู่ระบบ" พร้อม `WWW-Authenticate: Bearer`
- บัญชีที่ `must_change_password = true` → **403** "กรุณาเปลี่ยนรหัสผ่านก่อนใช้งาน" (ใช้ได้เฉพาะ `me` และ `password`)
- บัญชี `staff` ผ่านทุกเส้นทาง
- บัญชี `teacher`/`student` ที่ไม่มี `scope_id` หรือ role ไม่รู้จัก → **403**
- บัญชี `teacher`/`student` ได้สิทธิ์เฉพาะ 3 เส้นทางนี้ และต้องตรงกับบัญชีและตารางที่ใช้งานอยู่:
  1. `GET /api/schedule/active`
  2. `GET /api/schedule/versions/{version_id}/timetable` เมื่อ `version_id` คือเวอร์ชันที่ใช้งานอยู่, `view` ตรงกับบทบาท (`teacher` หรือ `group`), และ `id` = `scope_id` ของบัญชี
  3. `GET /api/reports/{key}` เมื่อ key คือ `teacher_timetables` (ครู) หรือ `group_timetables` (นักเรียน), `id` = `scope_id`, และ `version_id` ว่างหรือเป็นเวอร์ชันที่ใช้งานอยู่
- เส้นทางอื่นทั้งหมดสำหรับบทบาทนี้ → **403** "บัญชีนี้ไม่มีสิทธิ์ใช้งานส่วนนี้"
- ปิด guard ได้ด้วยตัวแปร `TIMETABLE_AUTH_DISABLED=1` **ใช้ในการทดสอบอัตโนมัติเท่านั้น** ห้ามตั้งค่านี้บน Render

## 5. การจัดการบัญชี (เฉพาะ staff)
- `GET /api/auth/users` รายการบัญชี พร้อมชื่อของครู/กลุ่มที่ผูกอยู่ (ถ้าข้อมูลถูกลบหรือนำเข้าใหม่ ให้แสดง "ไม่พบข้อมูล (ถูกลบ/นำเข้าใหม่)" เป็นสีแดง)
- `GET /api/auth/targets?role=teacher|student` รายชื่อครูหรือกลุ่มเรียนให้เลือกผูกบัญชี
- `POST /api/auth/users` สร้างบัญชีเดี่ยว: ชื่อผู้ใช้, รหัสเริ่มต้น (≥ 6), role, scope_id (ถ้าไม่ใช่ staff) เมื่อสร้างแล้วตั้ง `must_change_password = true` ชื่อซ้ำ → 409 "ชื่อผู้ใช้นี้ถูกใช้แล้ว"
- `POST /api/auth/users/bulk` สร้างบัญชีอัตโนมัติให้ครูทุกคนหรือกลุ่มเรียนทุกกลุ่มที่ยังไม่มีบัญชี (ข้ามรายการที่ `is_excluded`)
  - ชื่อผู้ใช้ = รหัสครู/รหัสกลุ่ม (ตัวเล็ก ไม่มีช่องว่าง) ถ้าซ้ำเติม `-2`, `-3`
  - รหัสเริ่มต้นสุ่มจากตัวอักษรที่ไม่คล้ายกัน ความยาว 8 ตัว (`abcdefghjkmnpqrstuvwxyz23456789`)
  - ให้ดาวน์โหลดเป็นไฟล์ CSV (มี BOM UTF-8) ชื่อ "บัญชีผู้ใช้-{role}.csv" ได้ **ครั้งเดียวตอนสร้าง** เพราะรหัสจะไม่แสดงอีก
- `PATCH /api/auth/users/{id}` แก้ได้: รหัสผ่านใหม่ (จะตั้ง `must_change_password = true` ให้เจ้าของเปลี่ยนเองเมื่อเข้าระบบ), ชื่อแสดง, เปิด/ปิดใช้งาน
- `DELETE /api/auth/users/{id}` ลบบัญชี (ตามข้อจำกัดในข้อ 2)
- หน้าบัญชีผู้ใช้แสดงตาราง: ชื่อผู้ใช้, ชื่อแสดง, บทบาท (ป้าย), ผูกกับ (ครู/กลุ่ม หรือ "ทั้งหมด" สำหรับ staff), สถานะ:
  - "ปิดใช้งาน" (เทา มีขีดฆ่า)
  - "ยังไม่เปลี่ยนรหัส" (เหลือง)
  - "ใช้งานอยู่" (เขียว)
- มีป๊อปอัปตั้งรหัสใหม่ให้บัญชี และป๊อปอัปสร้างบัญชีที่เลือกบทบาทและเลือกครูหรือกลุ่มจากรายการ (ปุ่มบันทึกปิดจนกว่าจะกรอกครบ)

## 6. หน้าเข้าสู่ระบบ (Login.tsx)
- พื้นหลังไล่สีจาก indigo-50 ผ่าน white ไป violet-50 การ์ดกลางจอกว้างสูงสุด 384px (max-w-sm) มีเงาอินดิโกบาง
- จอใหญ่ (lg) มีแผงซ้ายไล่สี indigo-600 → violet-700: โลโก้, ข้อความ "จัดตารางสอนทั้งหลักสูตร ในไม่กี่วินาที", ภาพตารางสอน และ 3 ขั้นตอนการใช้งาน
- หัวการ์ด: โลโก้ SVG 52px (LogoMark), ข้อความตัวหนา "ระบบจัดตารางสอนอัตโนมัติ" และหัวรอง "เข้าสู่ระบบ" สีเทา
- ฟอร์ม: ช่อง "ชื่อผู้ใช้" (autofocus, autocomplete `username`) และ "รหัสผ่าน" (type password, autocomplete `current-password`)
- ข้อความผิดพลาดแสดงใต้ฟอร์มเป็นตัวแดง ใช้ `role="alert"`
- ปุ่ม "เข้าสู่ระบบ" เต็มความกว้าง ปิดใช้งานขณะส่งหรือเมื่อยังไม่กรอกชื่อผู้ใช้/รหัสผ่าน ระหว่างส่งข้อความปุ่มเปลี่ยนเป็น "กำลังเข้าสู่ระบบ…"
- ข้อความท้ายฟอร์มสีเทาเล็ก: "นักเรียนและอาจารย์ขอชื่อผู้ใช้/รหัสผ่านจากผู้ดูแลเว็บไซต์" (ไม่มีลิงก์สมัครสมาชิก และไม่มีลืมรหัสผ่าน ต้องให้ผู้ดูแลเว็บไซต์รีเซ็ต)

## 7. หน้าเปลี่ยนรหัสผ่านบังคับ (ChangePasswordPage)
- ใช้การ์ดแบบเดียวกับหน้าล็อกอิน หัวรอง "ตั้งรหัสผ่านใหม่ก่อนใช้งาน"
- ข้อความ: "สวัสดี {ชื่อ} — กรุณาเปลี่ยนรหัสผ่านที่ได้รับเป็นรหัสผ่านของคุณเอง (อย่างน้อย 6 ตัวอักษร)"
- มี 3 ช่อง: รหัสผ่านปัจจุบัน, รหัสผ่านใหม่, รหัสผ่านใหม่อีกครั้ง
- ถ้ารหัสใหม่สองครั้งไม่ตรงกัน แสดง "รหัสผ่านใหม่ไม่ตรงกัน" (ตัวแดง)
- ปุ่ม "เปลี่ยนรหัสผ่าน" (หลัก) และ "ออกจากระบบ" (ghost) อยู่ข้างกัน
- ผู้ใช้เข้าเมนูอื่นไม่ได้จนกว่าจะเปลี่ยนรหัส

## 8. การจัดการสถานะล็อกอินฝั่ง frontend
- โทเคนเก็บใน **sessionStorage** คีย์ `ai-timetable-token` (หายเมื่อปิดแท็บ) ห้ามเก็บใน localStorage
- เมื่อเปิดแอปและมีโทเคน ให้เรียก `/api/auth/me`; ถ้าล้มเหลวให้ออกจากระบบและกลับไปหน้าล็อกอิน
- ทุกคำขอที่ได้ 401 ให้เรียก handler เพื่อออกจากระบบอัตโนมัติ
- ผู้ใช้ที่ `must_change_password = true` จะถูกพาไปหน้าเปลี่ยนรหัสผ่านก่อนเสมอ
- เมื่อเปลี่ยนรหัสสำเร็จ ให้เก็บโทเคนใหม่ที่ backend ส่งกลับมาทันที
- ใช้ React Context (`AuthProvider` / `useAuth`) ให้คอมโพเนนต์เรียก `user`, `loading`, `login`, `changePassword`, `logout`
- แสดงสถานะ `loading` ระหว่างตรวจโทเคนครั้งแรก ไม่แสดงหน้าใดจนกว่าจะรู้ผล

## 9. เมนูผู้ใช้ (UserMenu) บนแถบหัวด้านบนขวา
- แสดง "👤 {ชื่อแสดง} ({ป้ายบทบาท})" (ซ่อนชื่อบนมือถือ, เหลือเฉพาะ)
- ปุ่ม "เปลี่ยนรหัสผ่าน" (บนมือถือเป็นไอคอน 🔑) เปิดโมดัลที่มี 3 ช่องเหมือนหน้าเปลี่ยนรหัส และแสดงข้อความ "เปลี่ยนรหัสผ่านแล้ว" เป็นสีเขียวเมื่อสำเร็จ
- ปุ่ม "ออกจากระบบ" ล้างโทเคนและกลับไปหน้าล็อกอิน

## 10. ข้อกำหนดด้านความปลอดภัยและการใช้งานจริง
- ตั้งค่า `TIMETABLE_ADMIN_PASSWORD` และ `TIMETABLE_DATA_DIR` ใน Render ก่อนเปิดให้ใช้งาน และเปลี่ยนรหัสผ่านผู้ดูแลทันทีหลังล็อกอินครั้งแรก
- อย่าตั้ง `TIMETABLE_AUTH_DISABLED` บนเซิร์ฟเวอร์จริง
- ข้อความผิดพลาดทั้งหมดต้องไม่เปิดเผยว่าชื่อผู้ใช้มีอยู่หรือไม่
- ทุกการสร้าง แก้ไข ลบ บัญชี และการเปลี่ยนรหัสผ่านต้องไม่บันทึกรหัสผ่านลงในประวัติการแก้ไข (ChangeHistory) หรือ log
- ทดสอบอย่างน้อย: ล็อกอินถูกและผิด, ล็อก 429 หลังผิด 5 ครั้ง, โทเคนหมดอายุ, โทเคนเก่าใช้ไม่ได้หลังเปลี่ยนรหัส, บัญชี teacher เข้าตารางของคนอื่นไม่ได้, บัญชี student เข้า API ที่ไม่อนุญาตไม่ได้, บัญชี `must_change_password` ถูกบล็อก, ไม่สามารถปิดหรือลบ staff คนสุดท้ายได้
