# พรอมต์สไลด์: แนวทางสั่งทำสไลด์นำเสนอโครงงาน

## ส่วนที่ 1 หลักการ: บอกให้ครบ 7 เรื่องตั้งแต่ครั้งแรก

| เรื่อง | สิ่งที่ต้องบอก | ตัวอย่าง |
|---|---|---|
| 1. เป้าหมาย | นำเสนอเพื่ออะไร | นำเสนอโครงงานต่อคณะกรรมการสอบ |
| 2. ผู้ฟัง | ใครฟัง รู้เรื่องนี้มากน้อยแค่ไหน | กรรมการที่ไม่เคยเห็นระบบ ไม่ใช่โปรแกรมเมอร์ |
| 3. เวลา | นำเสนอกี่นาที | 12–15 นาที ประมาณ 15 สไลด์ |
| 4. เนื้อหา | หัวข้อทุกสไลด์ ตามลำดับ | ดูแม่แบบส่วนที่ 3 |
| 5. ภาษา | ระดับภาษาและคำต้องห้าม | ภาษาทางการ ห้ามใช้คำโฆษณา |
| 6. รูปแบบ | สี ฟอนต์ ภาพ ไอคอน | พื้นสีเข้ม ฟอนต์ Prompt กับ Sarabun |
| 7. ไฟล์ผลลัพธ์ | ต้องการไฟล์แบบใด | PDF และ PowerPoint พร้อมสคริปต์ในโน้ต |

ถ้าบอกไม่ครบ ต้องแก้หลายรอบ เช่นในโครงงานนี้ ต้องสั่งแก้ภาษา ฟอนต์ ผังงาน และคำศัพท์แยกกันหลายครั้ง

## ส่วนที่ 2 เทคนิคแยกตามเรื่อง

### 2.1 ล็อกข้อความที่ห้ามเปลี่ยน
- ใส่ข้อความที่ต้องการไว้ในเครื่องหมายคำพูด แล้วเขียนกำกับว่า "ใช้ข้อความนี้ทุกตัวอักษร"
- แยกให้ชัดว่าส่วนใด **ห้ามเปลี่ยน** และส่วนใด **ปรับได้อิสระ**
  > ตัวอย่าง: "ข้อความในสไลด์ห้ามเปลี่ยน ปรับได้เฉพาะสี รูปแบบ และการจัดวาง"
- ถ้าแก้ไฟล์เองแล้ว ให้แนบไฟล์ที่แก้ไปด้วย และสั่งว่า "ยึดข้อความในไฟล์ที่แนบ"

### 2.2 กำหนดระดับภาษาให้ชัด
- ระบุระดับภาษา: ทางการ กึ่งทางการ หรือภาษาพูด
- ระบุสิ่งที่ไม่ต้องการ แทนการบอกแค่ว่า "ห้ามใช้ภาษาเอไอ" เช่น
  - ห้ามใช้คำโฆษณา เช่น ล้ำสมัย อลังการ ปฏิวัติวงการ
  - ห้ามใช้อีโมจิ เครื่องหมายคำพูด และเครื่องหมายขีดยาว (—)
  - ห้ามใช้ประโยคคำคม หรือคำถามเชิงวาทศิลป์
  - ใช้คำศัพท์ที่คนทั่วไปเข้าใจ ถ้าจำเป็นต้องใช้ศัพท์เทคนิค ให้อธิบายในวงเล็บ
- กำหนดคำศัพท์ที่ต้องใช้ให้ตรงกันทั้งชุด เช่น "ใช้คำว่า สถานที่เรียน แทน ห้อง/สนาม" และ "ใช้คำว่า วิชา แทน บล็อก"

### 2.3 ให้ข้อมูลถูกต้อง
- แนบแหล่งข้อมูลจริง เช่น โค้ด ไฟล์ข้อมูล ผลการทดสอบ
- สั่งให้ตรวจข้อมูลกับแหล่งจริง:
  > "ตรวจสอบข้อความทุกข้อกับระบบจริง ถ้าข้อใดไม่ตรง ให้แก้และบอกว่าแก้อะไร"
- สั่งให้แยกสิ่งที่ทำแล้วกับสิ่งที่ยังไม่ได้ทำ:
  > "ข้อมูลที่ยังไม่ได้ทดสอบ หรือเป็นแผนในอนาคต ให้ระบุให้ชัด"
- ตัวเลขทุกตัวต้องมีที่มา ห้ามประมาณเอง เช่น "253 ชั่วโมง ใช้เวลาประมาณ 2 วินาที (จากการทดสอบ)"
- การเปรียบเทียบที่ไม่ได้ทดลองจริง ให้กำกับว่า "เปรียบเทียบตามหลักการ"

### 2.4 สั่งทำผังงาน (Flowchart)
- ระบุมาตรฐาน: "ใช้สัญลักษณ์ตามมาตรฐาน ANSI/ISO 5807"
- เขียนขั้นตอนเป็นข้อความก่อนสั่งวาด เช่น

  ```
  เริ่มต้น → กรอกชื่อผู้ใช้และรหัสผ่าน → ข้อมูลถูกต้อง?
    - ไม่ใช่ → กลับไปกรอกใหม่
    - ใช่ → นำเข้าไฟล์ Excel → ...
  → สิ้นสุด
  ```

- ระบุกฎเพิ่มเติม:
  - มีจุดเริ่มต้นและจุดสิ้นสุดเสมอ ใช้สีเดียวกัน
  - การตัดสินใจทุกจุดมีทางออก 2 ทาง กำกับว่า "ใช่" และ "ไม่ใช่"
  - ทุกทางออกต้องมีกล่องบอกว่าทำอะไรต่อ ห้ามปล่อยให้ผู้ฟังตีความเอง
  - เส้นต่อกันตลอด หรือใช้จุดเชื่อมต่อ A, B (ระบุว่าต้องการแบบใด)
  - ใส่คำอธิบายสัญลักษณ์ใต้ผังงาน
- แนบภาพตัวอย่างผังงานที่ชอบ จะได้ผลตรงที่สุด
- สั่งตรวจ: "ตรวจว่าผังงานตรงกับการทำงานจริงของระบบทุกขั้นตอน"

### 2.5 กำหนดรูปแบบการตกแต่ง
- บอกโทนและอารมณ์: เรียบหรู ทางการ สดใส หรือเทคโนโลยี
- บอกสีหลัก 1–2 สี และสีเน้น 1 สี
- บอกฟอนต์ภาษาไทย และขอให้ตรวจสระกับวรรณยุกต์ไม่หาย เช่น "ฟอนต์หัวข้อ Prompt ฟอนต์เนื้อหา Sarabun ตรวจสระบนและล่างครบทุกตัว"
- บอกว่าสร้างเป็นภาพทั้งหน้าได้หรือไม่
  - สร้างเป็นภาพ: สวยกว่า แต่แก้ข้อความใน PowerPoint ไม่ได้
  - ไม่สร้างเป็นภาพ: แก้ได้ แต่ตกแต่งได้จำกัดกว่า
- จำกัดเนื้อหาต่อหน้า เช่น "หน้าละไม่เกิน 4–6 ข้อ ข้อละไม่เกิน 2 บรรทัด"
- สั่งตรวจ: "ห้ามข้อความล้นกรอบ ห้ามตัดคำกลางคำ ห้ามองค์ประกอบทับกัน"

### 2.6 สั่งแก้เป็นรอบ ๆ
- แก้ทีละเรื่อง ระบุเลขสไลด์ทุกครั้ง: "สไลด์ 9 เปลี่ยนหัวข้อเป็น ..."
- แนบภาพหน้าจอแล้ววงกรอบจุดที่ต้องการแก้ ได้ผลแม่นที่สุด
- บอกทั้งของเดิมและของใหม่: "เปลี่ยนคำว่า A เป็น B"
- ถ้าไม่แน่ใจว่าถูกหรือผิด ให้ถามก่อนสั่งแก้: "ส่วนนี้ผิดไหม อธิบายให้เข้าใจ"
- ทุกครั้งที่แก้สไลด์ สั่งให้แก้สคริปต์ให้ตรงกันด้วย

### 2.7 ขอสคริปต์นำเสนอ
- ระบุภาษา: ภาษาพูดเป็นธรรมชาติ หรือภาษาทางการ
- ระบุจำนวนผู้นำเสนอ และการแบ่งช่วงพูด
- ระบุเวลาต่อสไลด์
- ขอคำถามที่กรรมการอาจถามพร้อมแนวคำตอบ
- ขอให้ใส่สคริปต์ในโน้ตของ PowerPoint เพื่อใช้กับ Presenter View

## ส่วนที่ 3 แม่แบบพรอมต์ (คัดลอกไปใช้ได้)

```
จัดทำสไลด์นำเสนอโครงงานเรื่อง "[ชื่อโครงงาน]"
จัดทำโดย [ชื่อผู้จัดทำ] [ชื่อสถานศึกษา]

[ผู้ฟังและเวลา]
- ผู้ฟัง: คณะกรรมการ ไม่ใช่ผู้เชี่ยวชาญด้านคอมพิวเตอร์
- เวลา: 12–15 นาที ประมาณ 15 สไลด์

[ลำดับเนื้อหา]
1. หน้าปก: ชื่อโครงงาน ภาษาอังกฤษ ผู้จัดทำ สถานศึกษา
2. ปัญหาของ [งานเดิม] (4 ข้อ)
3. แนวทางการแก้ปัญหา (จับคู่ปัญหากับวิธีแก้)
4. อัลกอริทึมที่ใช้ อธิบายเป็น 3 ขั้นตอน
5. เหตุผลในการเลือกอัลกอริทึม (ตารางเปรียบเทียบตามหลักการ)
6. ผังงานการทำงานของระบบ
7. ผังงานขั้นตอนวิธีของอัลกอริทึม
8. จุดเด่นที่สำคัญที่สุด พร้อมภาพหน้าจอจริง
9. จุดเด่นอื่นของระบบ
10–11. ตัวอย่างจากระบบจริง (ภาพหน้าจอ)
12. ประโยชน์ที่หน่วยงานจะได้รับ
13. ประโยชน์ต่อผู้ที่เกี่ยวข้อง
14. แนวทางการพัฒนาในอนาคต
15. หน้าขอบคุณ

[ภาษา]
- ภาษาทางการ เข้าใจง่าย สั้นกระชับ
- ห้ามใช้คำโฆษณา อีโมจิ เครื่องหมายคำพูด และเครื่องหมายขีดยาว
- ใช้คำศัพท์เดียวกันทั้งชุด: [คำที่ต้องใช้]

[ความถูกต้อง]
- ข้อมูลทุกข้อต้องตรงกับระบบจริง ตรวจสอบกับ [โค้ด/ไฟล์ข้อมูล] ที่แนบ
- ตัวเลขต้องมาจากผลการทดสอบจริง
- ระบุสิ่งที่ยังไม่ได้ทดสอบหรือยังเป็นแผนให้ชัด

[ผังงาน]
- ใช้สัญลักษณ์มาตรฐาน ANSI/ISO 5807
- มีจุดเริ่มต้นและสิ้นสุดสีเดียวกัน การตัดสินใจทุกจุดกำกับ ใช่/ไม่ใช่
- ทุกทางออกมีกล่องบอกการทำงาน เส้นต่อกันตลอด มีคำอธิบายสัญลักษณ์

[การตกแต่ง]
- โทน [ทางการ/เทคโนโลยี] สีหลัก [สี] สีเน้น [สี]
- ฟอนต์หัวข้อ [ฟอนต์] ฟอนต์เนื้อหา [ฟอนต์] ตรวจสระและวรรณยุกต์ครบ
- ทุกหน้ามีภาพหรือไอคอน หน้าละไม่เกิน 6 ข้อ
- สร้างเป็นภาพทั้งหน้าได้

[ผลลัพธ์]
- ไฟล์ PDF และ PowerPoint
- สคริปต์นำเสนอภาษา [ทางการ/ธรรมชาติ] ใส่ในโน้ตของแต่ละสไลด์
- แนวคำตอบคำถามที่กรรมการอาจถาม

[การตรวจสอบก่อนส่ง]
- ตรวจภาพทุกหน้า: ข้อความไม่ล้น ไม่ตัดคำกลางคำ ไม่ทับกัน
- สรุปสิ่งที่ทำและสิ่งที่ยังไม่ได้ตรวจสอบ
```

## ส่วนที่ 4 ข้อผิดพลาดที่พบบ่อย และวิธีป้องกัน

| ปัญหาที่พบ | วิธีป้องกันในพรอมต์ |
|---|---|
| สระหรือวรรณยุกต์หาย | ระบุฟอนต์ไทย และสั่งตรวจสระบนและล่าง |
| ข้อความเปลี่ยนไปจากที่แก้ไว้ | แนบไฟล์ และสั่งว่า "ยึดข้อความในไฟล์ที่แนบ" |
| ภาษาดูเหมือนเอไอเขียน | ระบุคำและเครื่องหมายต้องห้ามให้ชัด |
| ข้อมูลเกินจริง | สั่งตรวจกับระบบจริง และให้ระบุสิ่งที่ยังไม่ได้ทดสอบ |
| ผังงานอ่านยากหรือผิดหลัก | เขียนขั้นตอนเป็นข้อความก่อน และระบุมาตรฐานสัญลักษณ์ |
| ใช้ศัพท์เทคนิคจนผู้ฟังไม่เข้าใจ | ระบุผู้ฟัง และกำหนดคำศัพท์ที่ต้องใช้ |
| สไลด์กับสคริปต์ไม่ตรงกัน | สั่งให้แก้สคริปต์ทุกครั้งที่แก้สไลด์ |
| ภาพหน้าจอมีข้อมูลส่วนบุคคล | สั่งให้ใช้ข้อมูลตัวอย่าง หรือแจ้งเตือนก่อนใช้ข้อมูลจริง |
